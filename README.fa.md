۱. تفاوت Chatbot و Agent چیست؟









Chatbot — چت‌بات
کاربر سؤال می‌پرسد، مدل پاسخ می‌دهد و تمام.
مثال: «هوش مصنوعی چیست؟»
چت‌بات توضیح می‌دهد و منتظر سؤال بعدی می‌ماند.












AI Agent — عامل هوش مصنوعی
کاربر یک هدف می‌دهد و عامل برای رسیدن به آن، مراحل لازم را انتخاب و اجرا می‌کند.
مثال: «برای امشب ساعت ۷ یک رستوران ایتالیایی مناسب پیدا کن.»
عامل جست‌وجو می‌کند، اطلاعات را بررسی می‌کند و در صورت داشتن ابزار و مجوز لازم، رزرو را انجام می‌دهد.



خلاصه: چت‌بات بیشتر پاسخ تولید می‌کند؛ Agent علاوه بر پاسخ‌دادن، می‌تواند تصمیم بگیرد و اقدام کند.
۲. عامل هوش مصنوعی چگونه کار می‌کند؟
چهار بخش اصلی دارد:
بخش	معنی	توضیح ساده
Perception	درک محیط	فهمیدن هدف کاربر و اطلاعات موجود
Reasoning	استدلال	تصمیم‌گیری درباره قدم بعدی
Action	اقدام	استفاده از ابزارها و اجرای عملیات
Evaluation	ارزیابی	بررسی نتیجه و تصمیم‌گیری برای ادامه کار
مثلاً اگر عامل نتواند برای ساعت ۷ میز پیدا کند، نتیجه را بررسی می‌کند و شاید ساعت ۷:۳۰ یا رستوران دیگری را پیشنهاد دهد.
این روند را Agent Loop می‌گویند؛ یعنی چرخه تکرارشونده تصمیم‌گیری، اجرا و بررسی نتیجه.
۳. معنی بخش‌های مختلف مسیر یادگیری
این فایل ۱۰ مرحله برای یادگیری پیشنهاد می‌دهد.

مرحله ۱ — Python Basics | مبانی پایتون
یادگیری متغیرها، توابع، کلاس‌ها، ماژول‌ها، مدیریت خطا و کار با API.
این‌ها پایه برنامه‌نویسی عامل هستند.




مرحله ۲ — Environment Management | مدیریت محیط
آشنایی با فایل .env، کلیدهای API و فایل requirements.txt.
هدف این است که کلیدهای محرمانه را امن نگه داری و وابستگی‌های پروژه را مدیریت کنی.




مرحله ۳ — Connect to LLMs | اتصال به مدل زبانی
یادگیری SDK شرکت OpenAI و سرویس OpenRouter.
با این روش، برنامه پایتون تو می‌تواند از مدل‌های زبانی استفاده کند. OpenRouter امکان دسترسی به مدل‌های ارائه‌دهندگان مختلف را فراهم می‌کند.




مرحله ۴ — Prompt Engineering | مهندسی پرامپت
یادگیری نوشتن دستورهای دقیق برای مدل.
- System Prompt: نقش و قوانین مدل
- Role Definition: تعریف نقش
- Instructions: دستورالعمل‌ها
- Few-shot Examples: چند نمونه ورودی و خروجی برای هدایت مدل




مرحله ۵ — Tool Calling | فراخوانی ابزار
عامل یاد می‌گیرد چه زمانی از ابزار استفاده کند و چگونه نتیجه آن را دریافت کند.
مثلاً اجرای تابع پایتون، جست‌وجوی وب یا خواندن اطلاعات دیتابیس.
این مرحله یکی از مهم‌ترین قدم‌ها برای تبدیل یک برنامه ساده LLM به عامل است.




مرحله ۶ — Build Simple Agents | ساخت عامل‌های ساده
ساخت پروژه‌های عملی مثل:
- Research Agent: عامل تحقیق و جست‌وجو
- Data Analysis Agent: عامل تحلیل داده
- File Assistant Agent: دستیار فایل
- Web Search Agent: عامل جست‌وجوی وب




مرحله ۷ — Memory | حافظه
عامل می‌تواند اطلاعات مکالمات قبلی، ترجیحات کاربر و اطلاعات پروژه را نگه دارد.
- Embeddings: تبدیل متن به بردارهای عددی
- Vector Database: ذخیره و جست‌وجوی بردارها
- RAG: بازیابی اطلاعات مرتبط و استفاده از آن‌ها هنگام پاسخ‌گویی




مرحله ۸ — LangGraph | مدیریت جریان اجرای عامل
برای طراحی گردش‌کارهای پیچیده، مدیریت وضعیت و تعیین مسیرهای مختلف اجرا استفاده می‌شود.
مثلاً اگر اطلاعات کافی بود، گزارش بساز؛ اگر نبود، دوباره جست‌وجو کن.




مرحله ۹ — MCP | پروتکل اتصال مدل به ابزارها
Model Context Protocol استانداردی برای ارتباط برنامه‌های هوش مصنوعی با ابزارها و منابع خارجی است.
مثلاً اتصال عامل به فایل‌ها، دیتابیس‌ها و برنامه‌های دیگر از طریق سرور MCP.




مرحله ۱۰ — Multi-Agent Systems | سیستم‌های چندعاملی
چند عامل تخصصی با یکدیگر همکاری می‌کنند.
مثلاً عامل اول تحقیق می‌کند، عامل دوم گزارش می‌نویسد و عامل سوم گزارش را بررسی می‌کند.



۴. اصطلاحات فنی مهم فایل
اصطلاح	معنی ساده
LLM	مدل زبانی بزرگ، مانند مدل‌های گفت‌وگومحور
API	راه ارتباطی برنامه تو با یک سرویس
OpenAI SDK	کتابخانه‌ای برای ارتباط برنامه با APIهای سازگار
OpenRouter	سرویس دسترسی به مدل‌های زبانی مختلف
Tool Calling	درخواست مدل برای اجرای یک ابزار مشخص
Memory	نگهداری اطلاعات برای استفاده در مراحل بعد
RAG	جست‌وجوی اسناد مرتبط و واردکردن آن‌ها به زمینه پاسخ
LangChain	ابزارهایی برای ساخت برنامه‌های مبتنی بر مدل‌های زبانی
LangGraph	ابزار طراحی جریان‌های اجرایی و عامل‌های دارای وضعیت
MCP	استاندارد ارتباط با ابزارها و منابع اطلاعاتی
Multi-Agent	همکاری چند عامل با نقش‌های متفاوت
۵. معماری نهایی عامل چه معنایی دارد؟
در نمودار پایانی، کاربر یک هدف تعیین می‌کند. عامل با استفاده از استدلال و حافظه، ابزار مناسب را انتخاب می‌کند، روی محیط بیرونی اقدام انجام می‌دهد و نتیجه را ارزیابی می‌کند.
مثلاً در یک عامل تحلیل فروش:
1. کاربر درخواست گزارش فروش ماهانه می‌دهد.
2. عامل تشخیص می‌دهد که باید داده‌ها را از دیتابیس بخواند.
3. ابزار پایتون داده‌ها را تحلیل می‌کند.
4. عامل نتیجه را بررسی می‌کند.
5. گزارش نهایی را به کاربر تحویل می‌دهد.
البته همه عامل‌ها الزاماً به حافظه بلندمدت یا چندین ابزار نیاز ندارند؛ معماری به هدف پروژه بستگی دارد.
۶. این نقشه راه در نهایت چه می‌گوید؟
مسیر کلی این است:
LLM Application
برنامه‌ای که از مدل زبانی استفاده می‌کند

Tool Calling
مدل می‌تواند ابزار مناسب را درخواست کند

AI Agent
تصمیم‌گیری، اجرا و ارزیابی در یک چرخه

Advanced Agent Systems
عامل‌های پیچیده و سیستم‌های چندعاملی
